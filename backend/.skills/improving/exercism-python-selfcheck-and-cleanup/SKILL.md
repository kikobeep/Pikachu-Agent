## When to use
- 任务要求只实现某个 .py 文件，正式测试隐藏、无法查看。
- 已读完 stub，需要在不新建测试文件的前提下验证逻辑。
- 题目规则复杂（状态搜索、编解码、矩阵变换、解析器）时，单靠示例不足以确认边界。

## Instructions
1. 先读 stub，确认必须保留的类名、函数名与签名，只在该文件内做最小实现。
2. 用 `python3 -c` 或 heredoc 内联脚本导入实现，覆盖：题目给出的示例、空/退化输入、以及题目规则涉及的边界分支。
3. 规则复杂时另写一个结构不同的参考实现（如朴素枚举或独立 BFS），对随机输入做差分对比，定位不一致的边界。
4. 若需落盘脚本，用临时文件名（如 selfcheck_tmp.py）放在工作目录，运行后删除该脚本；不要创建或修改任何测试文件。
5. 只清理本次创建的临时文件；不要删除项目已有文件或运行时缓存目录。

## Verification
- 内联/临时脚本全部断言通过，且题目示例输出与预期一致。
- 差分对比在大量随机输入上无差异。
- 结束后工作目录只剩题目要求的实现文件（及原有文件）。

## Example
```python
# python3 -c "from transpose import transpose; assert transpose('AB\nDEF')=='AD\nBE\n F'"
```
复杂规则时再写一个独立参考实现，对随机输入逐一比对结果。
